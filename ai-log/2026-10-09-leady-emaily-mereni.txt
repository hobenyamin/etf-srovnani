     Nové balíčky
     - @supabase/supabase-js: oficiální klient, přes HTTP (Data API). Funguje na

     - server-only: když se lib/supabase.ts omylem importuje do klientského
       kódu, build selže. Tajný klíč se tak nedostane do prohlížeče.

     Migrace supabase/migrations/20261009_leads.sql (spustíte ručně v SQL
     editoru):
     - Tabulka public.leads se sloupci z CLAUDE.md: id uuid pk default
       gen_random_uuid(), email, created_at, consent_text, consent_at,
       double_opt_in_at, utm_source/medium/campaign/content, ad_variant,
       calc_input jsonb, calc_result jsonb, user_agent.
     - Doplňky (zdůvodním v README):
       - marketing_consent boolean not null default false. consent_text a
         consent_at platí pro souhlas s novinkami, bez souhlasu null.
       - notice_text: znění informace u formuláře (CONSENT.delivery + správce),
         aby bylo jasné, co návštěvník viděl.
       - confirm_token_hash, confirm_sent_at: token pro 4b. V DB je jen SHA-256
         hash, ne token.
       - unsubscribed_at, has_broker (nepovinná otázka z děkovací obrazovky,
         dnes jen TODO v ThankYou.tsx:219).
     - Unikátní index na lower(email). Opakované odeslání nepřepíše první
       atribuci (UTM, varianta). Jen doplní souhlas s novinkami, pokud ho
       návštěvník nově udělil. Nevytváří duplicitní lead.
     - check omezení: ad_variant in ('a','b'), has_broker in (…), délky textů.
     - alter table … enable row level security, žádné politiky.
     - revoke all … from anon, authenticated, grant select, insert, update on
       public.leads to service_role. Nové tabulky ve vašem projektu se do Data
       API nevystavují, proto je explicitní grant pro service_role nutný. Jinak
       tajný klíč dostane „permission denied“. Tohle ověříte v kontrolním bodě.
     - IP adresa se nikde neukládá.
     - Doba uložení: nepotvrzené leady se mažou po 30 dnech.
       - Funkce public.purge_unconfirmed_leads() (security definer, search_path
         pevně nastavený, execute jen pro postgres): delete from leads where
         double_opt_in_at is null and created_at < now() - interval '30 days'.
         Vrací počet smazaných řádků.
       - Naplánování přes pg_cron: create extension if not exists pg_cron; a
         select cron.schedule('purge-unconfirmed-leads', '15 3 * * *', 'select
         public.purge_unconfirmed_leads()'), tedy denně ve 3:15 UTC.
         cron.schedule se stejným názvem úlohu přepíše, takže migrace jde
         spustit opakovaně.
       - pg_cron je podle dokumentace Supabase dostupný i na free plánu. Ověřím
         to při implementaci. Kdyby create extension v SQL editoru selhal, zapne
         se v Dashboardu: Integrations → Cron (nebo Database → Extensions →
         pg_cron). Pak se spustí jen část cron.schedule; v migraci budou
         oddělené komentářem.
       - Záložní varianta, pokud pg_cron nepůjde: Vercel Cron (Hobby povoluje 1×
         denně) zavolá route handler /api/cron/purge chráněný CRON_SECRET. Ten
         spustí stejnou funkci přes RPC. Implementuji jen v případě potřeby.
       - Riziko: free projekt Supabase se po týdnu nečinnosti uspí a cron pak
         neběží. Zapíšu do „Co chybí“; pro ostrý provoz to řeší Pro plán.

     E-mail (lib/email.ts a lib/email-template.ts, česky):

       List-Unsubscribe + List-Unsubscribe-Post (one-click) → route handler
       POST /api/odhlaseni.
     - 480/2004: tento e-mail je vyřízení žádosti, ne obchodní sdělení, takže v
       něm není žádná propagace. Pravidlo pro budoucí novinky zapíšu do kódu

       rozesílání v tomto kroku nebude.

     - app/odhlaseni/page.tsx: tlačítko „Odhlásit“ → nastaví unsubscribed_at a

     Nové balíčky
     - posthog-js: oficiální SDK. Načte se dynamickým import() až po souhlasu,
       takže bez souhlasu se nestáhne ani nespustí. Zároveň nezatěžuje LCP.
